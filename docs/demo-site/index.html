01 -- THE FAILURE BOUNDARY

A Missing Response Is Not Proof of a Missing Execution

Ambiguous Timeouts

When a client times out, it cannot know if the server executed the request, is still executing, or never received it. The uncertainty is the core problem.

Dangerous Retries

Retrying without stable task identity risks double-execution of critical operations: duplicate payments, duplicate bookings, repeated external API calls.

Heterogeneous Adapters

Different agent adapters represent context and lifecycle differently. A common correlation schema is needed for reliable cross-adapter communication.

Crash Recovery

A server process crash between accepting work and committing results leaves state in limbo. The system must reconcile or resume safely on restart.

03 -- IDENTITY MODEL

Three Identities, One Logical Task

STABLE

dialog_id

dlg_payment_2024_q4

Persistent correlation identifier for the long-lived conversation or workflow. Remains the same across all retries, all operations, and all process restarts.

Scope: Entire conversation
STABLE

idempotency_key

pay_inv_42_v1

Client-chosen unique key for one intended business side effect. Two requests with the same key and same payload are deduplicated. Different payloads trigger 409 Conflict.

Scope: One business operation
DYNAMIC

request_id

req_a7b3c9d4e1f2

Fresh UUID generated for every HTTP transmission attempt. Even if the same logical task is retried, each wire-level request carries a unique request_id.

Scope: One network transmission
COUNTER

attempt

1, 2, 3, ...

Monotonically increasing integer tracking how many times Adapter A has transmitted this logical request. Used for retry policy decisions and audit.

Scope: Retry sequence

06 -- VERIFIED INVARIANTS

What This System Guarantees

VERIFIED

No Duplicate Side Effects

Domain action ledger checks executed records in single transaction before commit.

VERIFIED

Idempotent Retry Safety

Completed operations return cached response; running operations return 202 In Progress.

VERIFIED

Crash Durability

Uncommitted work rolls back cleanly; committed work survives SIGKILL process termination.

VERIFIED

Identity Preservation

dialog_id and idempotency_key are preserved across retries and crashes.

VERIFIED

Payload Integrity

Reusing an idempotency key with different payload triggers HTTP 409 Conflict.

VERIFIED

Concurrent Serialization
